1. Executive Summary & Architectural Overview

Samudra Rakshak (also codenamed Sagar Suraksha) is an integrated multi-sensor underwater anomaly detection and real-time surface maritime tactical feed platform engineered for the Smart India Hackathon (SIH 26057) under the Ministry of Earth Sciences (MoES).

Traditional side-scan sonar (SSS) interpretation relies on human hydrographers manually inspecting large-volume acoustic waterfalls, a process prone to visual fatigue and high latency during emergency search-and-rescue (SAR) or subsea asset monitoring operations. Samudra Rakshak bridges this gap by unifying:

  • Subsea AI Detection: Automated localized bounding box detection, semantic tagging, and anomaly score evaluation on acoustic side-scan sonar images.
  • Geographic Coordinate Mapping: Transformation of 2D towfish acoustic swath coordinates into WGS84 ellipsoidal coordinates $( ext{Lat}, ext{Lon})$ with dynamic buffer zones.
  • Live Surface AIS Maritime Feeds: Global real-time Automatic Identification System vessel ingestion via WebSockets with continuous kinematic simulation.
  • Subsea-to-Surface Hazard Alerting: Continuous geodesic proximity distance calculation triggering automated Level-4 SOS alerts when surface vessels enter active debris danger exclusion zones.
  • Multi-Source Maritime Incident Intelligence: Multi-tier aggregation across NOAA, USCG, NGA, INCOIS, Indian Coast Guard, and news RSS feeds with AI deduplication clustering.
System Architecture Topology: The application follows a strictly decoupled asynchronous architecture. The backend is orchestrated in Python 3.11+ using FastAPI, PyTorch, Ultralytics, and SQLAlchemy Async, while the frontend is constructed in React 18 with Vite, Tailwind CSS, and Leaflet.js rendering sub-second GIS telemetry.

4. Machine Learning Pipeline & Model Training

The core AI pipeline utilizes a specialized Two-Stage Hybrid Architecture specifically optimized for underwater acoustic side-scan sonar imagery.

4.1 Stage 1: Fine-Tuned YOLOv8n Sonar Object Detector

Standard pre-trained optical models (like COCO weights) perform poorly on sonar data due to the lack of color channels, unique acoustic specular highlights, acoustic shadows behind objects, and non-uniform acoustic transmission loss.

We trained a custom YOLOv8n-Sonar detector (sonar_v2.pt) on an annotated dataset of 10 subsea debris and hazard classes:

4.2 Hyperparameters & Training Objective

The model was trained using the complete YOLOv8 multi-task loss objective combining Complete IoU (CIoU), Distribution Focal Loss (DFL), and Binary Cross-Entropy (BCE) classification loss:

Losstotal = λbox · LossCIoU + λcls · LossBCE + λdfl · LossDFL
(where λbox = 7.5, λcls = 0.5, λdfl = 1.5)
  • Optimizer: SGD with Nesterov momentum (m = 0.937)
  • Learning Rate Schedule: Cosine Annealing (lr0 = 0.01, lrfinal = 0.0001)
  • Weight Decay: 0.0005
  • Batch Size: 16
  • Epochs: 100 with Early Stopping patience of 15
  • Augmentation Pipeline: Mosaic (0.8), Mixup (0.1), Random Perspective (±0.001), HSV-V adjustment (±0.4), Horizontal Flip (0.5).

4.3 Stage 2: Secondary Crop Classifier & Out-of-Distribution (OOD) Scoring

To prevent false alarms from natural seabed reverberation and reef formations, detected bounding boxes are dynamically cropped and evaluated by a secondary PyTorch classifier (CropClassifier in ml/classifiers/crop_classifier.py):

  1. The localized crop is normalized and passed through a lightweight convolutional feature extractor.
  2. Computes a temperature-scaled Energy Score:
    E(x; T) = −T · ln ∑i=1..K efi(x) / T   (T = 1.0)
  3. If the energy score exceeds the threshold τood = 0.850 and softmax confidence τconf = 0.250, the candidate is verified as an authoritative submerged debris object; otherwise, it is down-weighted as seabed clutter.

5.2 Geodesic Projection & Dynamic Hazard Geofences

Every detected debris object in image space (u, v) is georeferenced using the towfish sensor state (Lattf, Lontf, Headingtf, Altitudetf):

  1. Across-Track Offset (Δx): Metric distance along the port or starboard sonar beam perpendicular to the towfish heading.
  2. Along-Track Offset (Δy): Metric distance along the travel direction based on ping index spacing.
  3. WGS84 Transformation: Metric offsets are projected onto Earth's reference ellipsoid:
    ΔLat = (Δy · cos(θ) − Δx · sin(θ)) / 111,132.95
    ΔLon = (Δy · sin(θ) + Δx · cos(θ)) / (111,412.84 · cos(Lattf))
  4. Dynamic Safety Buffer Radius (Rgeo):
    Rgeo = Rbase + (0.5 · Altitudetf) + Wseverity
    Typical exclusion buffers range from 35m (low hazard) to 250m+ (submerged wreckage / ordnance).

6. Live AIS Stream Ingestion & Multi-Source Maritime Intelligence

6.1 AISStream Global Telemetry Engine (backend/services/ais_service.py)

The system interfaces with AISStream (wss://stream.aisstream.io/v0/stream), the international live AIS stream network operating under standard ITU-R M.1371 specifications.

  • Dual-Mode Continuous Engine: When an API key is provided, it connects to live worldwide satellite and terrestrial receivers. Simultaneously, an active kinematic engine propels an authoritative fleet of 36+ commercial and naval vessels across all major maritime corridors (Palk Strait, Suez Canal, Malacca Strait, Strait of Hormuz, English Channel, Panama Canal, and Gibraltar).
  • Subsea Proximity Collision Warning: Every 2.5 seconds, the service computes great-circle Haversine distances between all surface vessels and active sonar debris geofences:
    d = 2 · Rearth · arcsin(√[sin2(Δφ/2) + cos(φ1)cos(φ2)sin2(Δλ/2)])
    If d ≤ Rgeofence, an automated PROXIMITY_BREACH Level-4 SOS alert is broadcast over WebSockets to all connected client consoles.
